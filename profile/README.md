<p>「让账号在常用城市保持稳定登录环境」这句话，如果只当成一句口号，落地时无从下手。拆成参数就不一样了：出口城市、ASN 类型、时区、语言、出口漂移频率、心跳间隔、并发占用、以及每号带宽预算，八个量一列，哪些该固定、哪些可以浮动、偏离之后会看到什么现象，都能量化。这篇是参数说明书，把推荐取值和核对方式写清楚，照着配一遍，环境一致性就有了可比的基准。</p>

<h2>一、账号的「稳定登录环境」由八个参数决定</h2>
<p>八个参数分两组：网络侧四个决定「你从哪里来」，环境侧四个决定「你用的是什么设备」。两组必须互相吻合，只有网络侧对齐而环境侧错位，反而更显眼。</p>
<h3>网络侧四个</h3>
<p>出口城市、出口 ASN 类型（住宅或机房）、出口漂移频率、以及每号的并发占用。前三项决定账号在平台侧呈现的来源特征，第四项决定多号同时在线时会不会互相挤。</p>
<h3>环境侧四个</h3>
<p>系统时区、浏览器语言、屏幕分辨率、以及本地会话痕迹。前三项要与出口城市自洽，第四项要保证每个号独立，不与其他号共享同一份 Cookie 与本地存储。</p>

<h2>二、参数取值范围：逐项说明</h2>
<p>推荐取值不是唯一正确答案，而是经过实践检验、偏离代价较小的区间。取值落在区间内，一致性容易维持；落在区间外，需要额外的理由。</p>
<h3>城市与 ASN</h3>
<p>城市建议锁定到具体城市，不要只锁定国家。同一国家内不同城市相距几百上千公里，登录地来回跳很容易被记下来。ASN 类型应当是住宅宽带，机房段即使地理位置正确，运营商归属也对不上。判断方法看 ipinfo.io 返回的 org 字段，住宅宽带通常带运营商名称，机房则常见托管商名称。</p>
<h3>时区与语言</h3>
<p>时区必须与出口城市一致，这是最容易被忽略的一项。出口在洛杉矶、系统时区却是东八区，两者的矛盾比 IP 本身更明显。语言建议与城市常用语言一致，浏览器首选语言与 Accept-Language 头要同时对，只改一处等于没改。</p>

<h2>四、怎么核对：三个查询入口与一条自查路径</h2>
<p>核对的价值在于「可复现」。同一项参数用两个来源交叉验证，比一个来源看三遍有用。</p>
<h3>ipinfo 与 ip-api 交叉验证</h3>
<p>ipinfo.io 的 json 接口给出 city、region、org 三段，适合看归属；ip-api.com 的 json 接口带 isp 与 as 字段，适合看运营商。两个来源的城市如果对不上，多半是 IP 库版本差异，此时以实际连接路由为准，再看 mtr 的末跳归属。三个信息相互印证之后，归属判断基本可靠。</p>
<h3>环境参数自查</h3>
<p>时区用浏览器控制台里的日期对象直接看偏移量；语言看 navigator.language 与请求头；分辨率看屏幕实际尺寸而非缩放后的值。三项抄在一张表里，与出口城市逐个对齐。这一步十分钟能做完，却是最常被跳过的一步。</p>

<h2>五、漂移监控：三条阈值</h2>
<p>参数配好只是起点，长期稳定靠监控。三条阈值覆盖最常发生的三类漂移，超过就动手，不要等异常出现。</p>
<h3>城市漂移</h3>
<p>一周内城市变化超过一次，视为异常，立刻查是否发生了线路切换；一个月内变化超过三次，直接换线。城市漂移往往伴随会话重置，是长任务中断的主要原因之一。</p>
<h3>时区与语言漂移</h3>
<p>时区偏移量变化超过一小时，或首选语言被系统更新改回默认值，都属于静默漂移。这类漂移不报错，只在平台侧留下矛盾记录。建议每周固定时间抽查一次，改回原值即可。</p>
<h3>登录窗口漂移</h3>
<p>统计每个号最近两周的登录时段，若从原先的白天集中变成凌晨集中，且不是人为调整，说明有人或脚本在非常规时段动过。这一项没有固定阈值，看的是「与历史习惯的偏离程度」，偏离超过一半就需要核查。</p>

<h2>常见问答</h2>
<h3>城市必须精确到市吗，同省可以吗？</h3>
<p>答：多数情况下建议到市。同省内不同城市在家宽归属上属于不同节点，登录地记录会体现差异。若该省资源紧张、只有一两个城市可供，退到省级也可接受，但要保证 ASN 与运营商一致。</p>
<h3>时区不一致影响有多大？</h3>
<p>答：属于低成本高收益的修正项。改时区不花钱，但出口与系统时区矛盾时，其他做得再细也会留下明显痕迹。优先级应当排在换线之前。</p>
<h3>八个参数要全部固定吗？</h3>
<p>答：网络侧四项尽量固定，环境侧四项中分辨率允许小范围浮动（同一机型的不同缩放），会话痕迹则必须独立。全部锁死反而不自然，关键是组合稳定、不与其他号重复。</p>
<h3>监控要花钱买工具吗？</h3>
<p>答：初期不必。一个每 30 分钟跑一次的脚本，记录出口城市与延迟，存成表格，就够用。等号数上到几十个、手工比对吃力时再考虑工具，别一上来就买。</p>
